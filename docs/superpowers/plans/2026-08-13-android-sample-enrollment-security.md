# Android Sample Enrollment and Permission Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Android quickstart into a test-mode enrollment and verification app gated by explicit camera, storage and location consent.

**Architecture:** Gradle maps the ignored local CLI configuration into a BuildConfig string. A small pure permission-policy unit decides the Android-version-specific permission set and whether the gate is satisfied; `VerifyActivity` renders the gate, collects an email and runs the existing SDK operations only after that policy approves.

**Tech Stack:** Kotlin, AndroidX Activity Result APIs, CameraX, Kotlin coroutines, Gradle Kotlin DSL, FaceCheck KMP SDK.

**Spec:** `docs/superpowers/specs/2026-08-13-android-sample-enrollment-security-design.md`

## Global Constraints

- Read `FACECHECK_API_KEY` only from root `local.properties`; never commit a tenant-owned key.
- Require camera, media-storage read and at least coarse location before starting CameraX or a network operation.
- Do not record, log or transmit location, image bytes, API keys, grants or email beyond the normal FaceCheck request.
- Keep the production grant policy intact; this sample flow is exercised with `lk_test_`.
